## Hard rules
1. **Minimal on-screen text.** The user said "keep less text". No captions, no titles, no labels, no bullets, no corner tags. Text only where the
   story truly needs it as an *in-world object* (a number on a timer, "$" amounts on a trading screen, a "WINNER" sign on a casino table, a clock face).
   Prefer icons, motion, props, colour. If you use text it is short (<=3 words), large, and part of the world. When in doubt, draw it instead.
2. **Look**: same as the hook. Faceless black-headed stickman, red hoodie (hero), painted gradient skies, parallax layers, orange rim-light from the sun side
   (right), soft shadows, blue-cyan "vision" grade with cyan additive ghosts of the future. Cinematic virtual camera (push-ins, whips, spring pull-outs, shake on hits).
   Every shot needs: a foreground layer or depth element, a light source/rim, and secondary motion (cloth flutter, dust, particles). No flat-UI look, no empty rectangles.
3. **Determinism**: a frame is a pure function of time. No Math.random/Date/timers/CSS transitions/carried state. Use `rng(seed)`/`hash1` (lib.js). Closed-form
   springs (`spring`, `track`). Plain browser globals, no modules/bundler. Canvas 2D, 1920x1080, ctx `g`.
4. **Performance**: the whole video is ~10,700 frames x 4 motion-blur sub-frames. Budget **<= 60 ms per drawFrame** on this GPU machine. Cache any heavy static
   layer in an offscreen canvas keyed by a constant (see world.js for the pattern; create lazily inside draw, never depend on frame order — building a cache on first use is fine
   as long as the result does not depend on t). Avoid per-frame `shadowBlur` on big shapes and giant gradients/filters; avoid `ctx.filter`.
5. **Do not edit shared files**: rigs.js, world.js, scenes.js, full.js, harness.js, lib.js, timeline.js, layout.js, render.mjs, index*.html. If you need something from them that is
   missing, build it in YOUR chapter file(s) (prefix every global you define with your chapter id, e.g. `ch3_drawBoxer`, to avoid collisions — all chapters share one global scope!).
   You may *call* anything they expose. Wrap each chapter in an IIFE and only export `CH.<id>`.
6. Hero state helpers are globals you can reuse from scenes.js: `shakeAt(t,t0,amp,decay,f)`, `win(t,a,b,fi,fo)`, `rampInt(u,d)`, `poseOf(c)`, `walkerSt(c,extra)`, `SIDEWALK_Y`, `CHAR_X`, `STRIDE`, `PHASE_UNIT`.
   `walkerPose`/`drawWalker`/`walkerJoints`/`drawBike`/`drawCar`/`drawTimerRing`/`palGhost`/`PAL_REAL` from rigs.js; `drawWorld/drawForeground/withLayer/project/drawShadow/postFX/visionGrade/flash/rgbSplit/GROUND` from world.js.
   Read rigs.js to see what else is possible (e.g. recolour `PAL_REAL` copies for other people: different hoodie colours; scale `s` for a small child; mirror with `facing:-1`).
   Other characters (thief, boxer, child, friends, crowd, trader) = the same stickman rig recoloured/scaled/posed. Vary hoodie colours so crowds read.

## Chapter module API
File `ch/<id>.js` registers `CH.<id> = { draw(g, lt, dur) }` where `lt` = seconds since chapter start (0..dur) and `dur` from `LAYOUT[id].dur`.
- Draw the complete frame for the chapter (world, characters, grade, effects). **Do NOT** call `postFX`, vignette/grain, or fade to black — `full.js` adds postFX and the chapter-boundary dip-to-black
  (0.3 s in, 0.35 s out; keep the first 0.3 s and last 0.35 s of your chapter calm/low-information). You *may* draw flashes / rgbSplit on hits.
- Leave graphics state balanced (save/restore) and reset `globalAlpha`/`globalCompositeOperation` before returning.
- Sync to narration: `LAYOUT[id].vo` = array of `{id,text,start,dur,end}` with times LOCAL to the chapter. **Read `layout.js` and plan each beat to hit the matching line.** Visual beats should
  *illustrate the sentence being spoken* at the moment it is spoken (e.g. "the mug slides off the counter" -> mug slides then). Keep the screen alive: a new composition/camera move at least every ~2.5 s, and never hold a static shot > 3 s without secondary motion.
- VO text for all chapters is in `script.json`; the picture should *show*, not repeat. Pacing: set pieces escalate; chapter ends on a clear button beat in the last ~0.8 s of the VO tail.
- The vision effect: when the hero "sees the future" show cyan ghost copies (additive, `palGhost(alpha)`) that play ~10 s ahead; use the blue `visionGrade` sparingly (it also makes frames dark) and draw the hero AFTER the grade so his hoodie stays red.
- Test: `node render.mjs --page index_full.html --stills "name:T,name:T"` -> shots/<name>.png where **T = LAYOUT[id].start + lt (global seconds)**; contact sheet:
  `node render.mjs --page index_full.html --contact "T1,T2,..." --cols 4` -> shots/contact.png (use your own prefix for stills; the contact.png file is shared, so copy/rename it right after generating: other agents write it too — better: render stills only and view them with the Read tool).
  Also render a **2 s moving clip** of your busiest moment to check speed: `node render.mjs --page index_full.html --from T --to T+2 --out out/<id>_test.mp4 --sub 2` and check the fps printed (aim >= 8 fps at sub 2 on this machine).
  Look at your stills with the Read tool (it shows images) and fix the worst problems: overlapping figures, characters too small, empty frames, flat colours, bad framing, clipped limbs, text overlap. Do 2-3 critique rounds.
- Tip: when `CH[id]` throws, the whole render page breaks. Wrap risky code defensively and verify that `drawFrame` runs for every 0.1 s over the chapter (write a quick node/playwright loop or render a --contact with ~40 times) with no `[pageerror]`.

## Audio side-contract: `ch/<id>.cues.json` (REQUIRED for each chapter)
Written by the chapter author; read by sfx_full.mjs (which converts local->global times via out/layout.json). Format:
```
{ "mood": "wonder|bright|tense|dark|hollow|warm|epic|quiet",     // overall music colour for the chapter
  "music": { "arc": [[from,to,intensity0to1], ...],             // local seconds; cover 0..dur
             "risers": [[from,to], ...],                          // tension risers (whoosh-up) ending on a hit
             "silence": [[from,to], ...] },                        // optional: music/ambience drops out entirely (for dramatic beats)
  "ambience": "city|indoor|casino|arena|wind|quiet|crowd|void",   // loop bed under the chapter
  "cues": [ {"t": 2.3, "type": "whoosh", "gain": 0.8, "len": 0.6}, ... ] }                // t local seconds
```
**SFX vocabulary** (the audio agent implements ALL of these; use only these `type`s; optional params in brackets; gain 0..1.5 default 1):
- movement: `step`, `stepRun` [n], `whoosh` [len, gain], `whooshFast` [len] (passby), `swish` (small cloth/air), `jump`, `land`, `slide` [len], `skid` [len], `bikePass` [peak,len], `vehiclePass` [peak,len,pitch] (car/truck doppler), `truckPass` [peak,len] (big engine+air), `carHorn` [len], `truckHorn` [len], `skateboardRoll` [len], `skateboardSlam`
- impacts: `thump`, `hit` (generic punch/body hit), `punch`, `punchMiss` (air whiff), `bigImpact` (cinematic boom), `boom` [len], `cutHit`, `flashHit`, `titleImpact`, `crack` (wood/concrete), `glassBreak`, `ceramicBreak`, `catchSoft` (something caught in a hand), `clink`, `ceramicClatter`
- sport/objects: `pingpongHit` [n], `pingpongBounce`, `bellRing` (boxing bell), `crowdGasp`, `crowdCheer` [len], `batCrack`, `ballSmack` (glove catch), `paddleHit`, `rouletteSpin` [len], `rouletteBall` [len] (ball rattling then settling), `chipStack`, `coinDrop`, `cashRegister`, `moneyCount` [len], `keyboardTyping` [len], `tickerBlips` [len] (trading screen beeps), `uiBlip`, `uiConfirm`, `uiError`, `phoneTap`, `phoneBuzz`, `alarmClock` [len], `doorOpen`, `doorSlam`, `knock`, `paperRustle`, `partyPopper`, `clap`, `laughTrack` [len] (cartoon-ish chuckle bed, synthesized crowd murmur), `cork`
- vision / sci-fi: `eyeOpen`, `eyeFlash`, `pullOut`, `tick` [n], `ghostWhoosh` [len,gain], `echoPop` [n], `timerStart`, `timerBeep` [n], `glitch` [len], `rewind` [len], `reverseSwell` [len], `heartbeat` [len, bpm], `riserShort` [len], `staticBurst` [len], `vhsTear`, `sonar`, `clockTick` [n], `clockStop`
- disaster: `rumble` [len, gain] (earthquake low rumble), `quakeCrack`, `debrisFall` [len], `buildingCreak` [len], `siren` [len], `sirenDistant` [len], `crowdPanic` [len], `glassRain` [len], `dust` (soft air puff), `explosionFar`
- emotion / mix: `gasp`, `sting` (short positive musical sting), `stingDark`, `stingWonder`, `swell` [len] (musical swell), `dropOut` [len] (low-pass+duck everything for a beat), `silenceHit` (sudden cut to silence then tiny sub thump), `birdsong` [len], `wind` [len], `rain` [len], `footstepsRun` [len]
Params are advisory; if a cue needs something that is not in the list, pick the closest and note it in your final report. 25-60 cues per chapter is typical (steps on key beats not every step).
Cue timing precision matters: put the cue at the exact visual moment of the hit (compute it from the same timeline constants your draw code uses; ideally share one `const T = {...}` between draw and cues, and write the JSON from a tiny node script `ch/<id>.build_cues.mjs`
that `require`s nothing from the browser — or just hand-write the numbers consistently with the timeline in your chapter file).
